# 拾墨 Shimo · 部署指南

面向「普通用户」的本地一键部署文档。两种方式任选其一，**均无需接触源码**：

| 方式 | 适合 | 依赖 | 源码保密 |
|---|---|---|---|
| ① Windows 便携版 exe | Windows 桌面用户 | 无（免装 Python/Node/Docker） | ✅ 包内无源码文件，仅编译后字节码 |
| ② Docker 镜像 | 任何平台（Win/Mac/Linux） | Docker Desktop / Docker Engine | ⚠️ 镜像层内含明文 Python 源码，可被解包还原 |

> 严格不希望他人看到源码时，请使用 **方式 ①**。

---

## 方式 ①：Windows 便携版（推荐）

### 安装

1. 从发布页下载 `Shimo-<版本>-win64.zip`（如 `Shimo-v0.1.0-win64.zip`）。
2. 解压到任意目录（如 `D:\Shimo`）。
3. 双击 `Shimo.exe`。

浏览器会自动打开 `http://127.0.0.1:8848`，首次访问按提示设置访问密码即可使用。

**就这么简单，不需要安装任何其他软件。**

### 首次运行提示处理

- **Windows SmartScreen「未知发布者」**：发行包未做代码签名，属正常现象。点击「更多信息 → 仍要运行」。
- **Windows 防火墙弹窗**：选择「允许访问」（仅本机使用时允许专用网络即可）。

### 数据在哪里

```
Shimo/           ← 解压目录（整个文件夹即应用本体）
├─ Shimo.exe
└─ data/         ← 应用数据（配置、会话、索引），首次运行自动创建
   └─ vault/     ← 你的知识文件（Markdown、附件），拷贝即备份
```

- **卸载**：关闭程序后删除整个 `Shimo` 文件夹即可，不写注册表、不留残留。
- **备份/迁移**：拷贝 `vault/`（知识文件）与 `data/`（配置），或直接在 Web 界面用「备份/恢复」功能。
- **升级**：下载新版 zip 解压，把旧目录里的 `vault/` 和 `data/` 复制到新目录即可。

### 常见问题

| 问题 | 解决 |
|---|---|
| 端口 8848 被占用 | 创建快捷方式时在目标后加参数，或用环境变量 `SHIMO_PORT=8849` 后双击 `Shimo.exe` |
| OCR 扫描件识别失败 | 需安装 [Microsoft Visual C++ 2015-2022 Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)（64 位） |
| 想改用其他端口 | 设置环境变量 `SHIMO_PORT`（如 8849）后启动 |

## 方式 ②：Docker（一条命令）

### 安装

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows/macOS）或 Docker Engine（Linux）。
2. 打开终端，执行：

```bash
docker run -d --name shimo \
  -p 8848:8848 \
  -v shimo-data:/app/data \
  -v shimo-vault:/app/vault \
  ghcr.io/<owner>/<repo>/shimo:latest
```

3. 浏览器打开 `http://127.0.0.1:8848`，首次访问设置访问密码。

> 首次登录也可以用环境变量预置密码：加 `-e SHIMO_INITIAL_PASSWORD=你的密码`。

### 常用操作

```bash
docker logs -f shimo        # 查看日志
docker restart shimo        # 重启
docker stop shimo && docker rm shimo   # 停止并移除容器（数据在卷里，不丢）
docker volume ls            # 数据卷：shimo-data / shimo-vault
```

### AI 功能配置（环境变量注入）

容器内无系统凭据库（keyring），AI 密钥**只能经环境变量注入**（永不落盘）：

```bash
docker run -d --name shimo -p 8848:8848 \
  -v shimo-data:/app/data -v shimo-vault:/app/vault \
  -e AI_CHAT_BASE_URL=https://api.openai.com/v1 \
  -e AI_CHAT_API_KEY=sk-xxx \
  -e AI_CHAT_MODEL=gpt-4o-mini \
  -e AI_EMBED_BASE_URL=https://api.openai.com/v1 \
  -e AI_EMBED_API_KEY=sk-xxx \
  -e AI_EMBED_MODEL=text-embedding-3-small \
  ghcr.io/<owner>/<repo>/shimo:latest
```

---

## AI 凭据：两种方式的区别

- **方式 ①（exe）**：可在 Web 界面「AI 设置」中保存 API Key —— 写入 **Windows 系统凭据库**（凭据管理器），JSON 永不落盘。
- **方式 ②（Docker）**：界面保存会提示「系统凭据库不可用」，请改用上方环境变量注入。

两种方式都支持环境变量 `AI_CHAT_*` / `AI_EMBED_*` 注入，且环境变量优先。

---

## 数据备份与恢复

- **Web 界面**：设置页提供「知识备份 / 完整备份」导出与恢复（含 SHA1 校验、原子替换）。
- **手动**：备份 `vault/`（exe 方式）或 `docker cp shimo:/app/vault .`（Docker 方式）。
- 恢复后需重新配置 AI 凭据（凭据不随备份导出，属安全设计）。

---

## 源码保密说明（重要）

- **方式 ① exe**：发行包只含编译后的 Python 字节码与资源文件，**不包含任何 `.py` 源码**（构建脚本内置检查）。字节码理论上可被专业反编译，但门槛高、还原度低，符合常规「不暴露源码」要求。
- **方式 ② Docker**：镜像层内为明文 `.py` 源码，`docker save` 解包即可读取。**对源码保密有硬性要求时，不要使用 Docker 方式分发。**

## 维护者：如何发布新版本

发布全程由 GitHub Actions 自动完成，**无需在本机构建**：

```bash
# 1. 更新版本号（可选）：app/version.py
# 2. 打标签并推送
git tag v0.1.1
git push origin v0.1.1
```

CI 自动产出并发布：

1. **Windows**：运行后端测试 → 构建前端 → PyInstaller 打包 → 上传 `Shimo-v0.1.1-win64.zip` 到 GitHub Release。
2. **Docker**：多架构构建（linux/amd64 + arm64）→ 推送 `ghcr.io/<owner>/<repo>/shimo:v0.1.1` 与 `:latest`。

> 前提：仓库已推送到 GitHub，且工作流首次运行已通过（Actions 页签可查看进度）。私有仓库也可发布，Release 与 GHCR 包默认继承仓库可见性。
