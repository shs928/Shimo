# 拾墨（Shimo）系统设计方案

> 版本：v1.1 ｜ 日期：2026-08-12 ｜ 状态：评审稿
>
> 定位：一个轻量、文件优先、单用户、可插拔 AI 的个人知识库，代号「拾墨（Shimo）」。本地双击即用，云端可部署，桌面和手机浏览器均可访问；知识内容始终是可直接读取和迁移的 Markdown 文件。

---

## 一、项目定位

### 1.1 核心目标

| 诉求 | 方案 |
|---|---|
| 个人使用 | 单用户 + 访问密码，不引入团队、租户和复杂权限模型 |
| 在线编辑 Markdown | 浏览器通过 FastAPI 读取和保存服务端 Vault 内的真实 `.md` 文件 |
| 层级文件管理 | 使用真实目录树，支持无限层级、新建、移动、重命名、回收站和恢复 |
| 本地部署 | Windows 便携版双击启动；源码版提供 `start.bat` / `start.sh` |
| 云端部署 | Docker Compose + Caddy，首次由部署支持人员完成配置 |
| 移动端使用 | 响应式 Web + PWA 安装能力，手机浏览器可浏览和编辑云端 Vault |
| 工程轻量 | FastAPI 单体后端、SQLite 可重建索引、无独立搜索或向量服务 |
| 数据可迁移 | Markdown 和附件保持普通文件结构，可被 Obsidian、Git 和其他工具直接使用 |

### 1.2 已确认的产品边界

- 知识文件保存在服务端 `vault/`。本地部署时它是本机目录，云端部署时它是服务器目录。
- Markdown 文件是知识内容的**唯一权威数据源**；SQLite 不保存唯一一份正文。
- 编辑器采用 CodeMirror 6，提供源码编辑、阅读预览、左右分屏三种模式。
- 首版兼容标准 Markdown、GFM、Obsidian WikiLink、YAML front matter、KaTeX 和 Mermaid。
- 页面参考思源笔记的工作区信息架构：左侧文件与大纲、中间多标签编辑区、右侧属性与知识关系，但不复刻思源的品牌视觉和块级编辑器。
- 首版是单用户、多设备先后编辑；不做多人实时协作、CRDT 或离线双向同步。

### 1.3 设计原则

1. **文件优先**：即使应用停止或索引损坏，用户仍能用任意文本编辑器读取全部知识。
2. **可靠写入**：原子保存、版本快照和冲突检测优先于复杂编辑效果。
3. **索引可重建**：全文搜索、反链、图谱和向量均是从 Vault 派生的数据。
4. **轻量部署**：构建工具不进入最终运行环境；生产运行时只有 Python 应用、SQLite 和静态前端。
5. **渐进增强**：未配置 AI 时，文件、搜索、链接、附件等功能完整可用。
6. **移动可操作**：手机端不是只读页面，文件导航、编辑、保存和搜索均有完整入口。
7. **默认安全**：文件系统严格限界；云端强制认证和 HTTPS；不默认对公网暴露本地实例。

### 1.4 首版规模目标

以下是设计与测试基线，不是硬限制：

- 10,000 个 Markdown 文件、50,000 条内部链接。
- 单个 Markdown 文件建议不超过 5 MB；超大文件仍可打开，但关闭实时预览。
- 附件总量可达到数十 GB，附件不写入 SQLite。
- 热索引状态下，常规全文搜索目标为 500 ms 内返回首屏结果。
- 本地文件保存目标为 500 ms 内完成；AI 调用不计入此目标。

## 二、总体架构

### 2.1 文件为主、索引为辅

```text
浏览器（Vue 工作台）
  │
  ├── 文件树 / 编辑 / 预览 / 搜索 / 反链 / 图谱 / AI
  │
  ▼ HTTPS / JSON API / SSE
FastAPI 单体应用
  ├── Vault 文件服务 ───────────────► vault/（权威知识数据）
  │     路径校验、原子保存、版本、回收站
  │
  ├── Markdown 解析与索引服务 ──────► data/index.db（可重建）
  │     FTS5、标题、标签、链接、向量
  │
  ├── 工作区与认证服务 ─────────────► data/config.json / workspace/
  │
  └── RAG 服务（可选） ─────────────► OpenAI 兼容 API 或本地 Ollama

文件监听器
  vault/ 外部变化 ─► 去抖与增量解析 ─► 更新索引 ─► SSE 通知浏览器
```

权威写入链路：

```text
CodeMirror 编辑
  → 携带 If-Match/ETag 调用保存 API
  → 校验路径和版本
  → 保存旧版本快照
  → 同目录临时文件写入、flush、原子替换
  → 解析新内容并提交索引事务
  → SSE 通知其他标签页/设备
```

### 2.2 数据目录职责

```text
vault/                         # 必须备份：用户的权威知识资产
├── 任意层级/**/*.md
├── assets/                    # 默认图片与附件目录
├── templates/                 # 可选模板
└── .trash/                    # 应用回收站，不参与搜索和 AI 索引

data/                          # 应用运行数据
├── index.db                   # 文件元数据、全文、标题、链接、标签、向量；可重建
├── config.json                # 认证哈希、服务设置、AI 配置（权限限制）
├── workspace/                 # 各设备的标签页、布局、折叠和最近访问状态
├── history/                   # 保存前的轻量版本快照
├── chats/                     # 可选 AI 会话记录
└── logs/                      # 轮转日志
```

备份分两种：

- **知识导出**：仅打包 `vault/`，不包含密码、API Key 和应用状态，可安全迁移给其他 Markdown 工具。
- **完整备份**：打包 `vault/`、`config.json`、`workspace/`、`history/` 和可选聊天记录；应加密保存。`index.db` 可省略，恢复后重建。

## 三、技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.11+、FastAPI、Uvicorn | 轻量，API 清晰，AI 生态成熟 |
| 文件监听 | watchfiles | 跨平台监听 Vault，支持异步和事件去抖 |
| 索引 | SQLite FTS5 | 单文件、零服务、适合个人知识库规模 |
| 向量 | sqlite-vec（可选加载） | 不引入独立向量数据库；AI 关闭时不加载 |
| 前端 | Vue 3 + TypeScript + Vite | 三栏、多标签、树和共享状态已超过原生 JS 的合理维护范围 |
| 编辑器 | CodeMirror 6 | Markdown 源码编辑、扩展性、移动端和长文档性能较好 |
| 渲染 | markdown-it + 插件、DOMPurify | GFM 和扩展语法可组合，渲染后统一消毒 |
| YAML | ruamel.yaml（后端） | 属性面板修改 front matter 时尽量保留未知字段、顺序和注释 |
| 数学/图表 | KaTeX、Mermaid（strict） | 成熟实现，避免自行解析公式和图表语法 |
| 图谱 | Cytoscape.js | 支持局部图谱、筛选和大图性能控制 |
| 图标 | lucide-vue-next | 统一、可访问的工具栏和导航图标 |
| 认证 | Argon2id + 签名 HttpOnly 会话 Cookie | 避免密码明文和令牌落入 localStorage |
| 本地发行 | PyInstaller `onedir` 便携包 | 双击启动且比单文件模式启动更快、杀软误报更少 |
| 云端 | Docker Compose + Caddy | 运行与 HTTPS 配置简单，数据卷边界明确 |

### 3.1 前端构建不会增加用户部署门槛

Vue 和 Node.js 只用于开发/发布阶段：

1. 发布时在 CI 或构建机执行 `npm run build`。
2. 生成的 `frontend/dist/` 是普通静态文件。
3. FastAPI 直接托管这些静态文件。
4. 本地用户和云端运行镜像均不需要 Node.js。

这比原生 JS 多一个开发构建步骤，但不会增加最终用户的一键启动成本，同时能显著降低多标签、文件树、面板联动和移动端状态管理的维护风险。

### 3.2 搜索的中文策略

- 英文和通用文本使用 FTS5 `unicode61`。
- 中文优先使用环境支持的 FTS5 `trigram`；启动时做能力检测。
- 若运行环境不支持 `trigram`，索引器生成 CJK bigram 搜索字段作为降级方案。
- 再降级时使用受限 `LIKE` 搜索，并在诊断页明确提示，不静默丢失结果。

## 四、Vault 与层级文件管理

### 4.1 真实目录树

- 递归展示 Vault 内真实目录和文件，支持任意层级展开、折叠与懒加载。
- 默认“目录优先 + 自然名称排序”，可切换名称、更新时间和类型排序。
- 记住每个设备的目录折叠状态、选中项和滚动位置。
- 支持新建 Markdown、文件夹，复制、重命名、拖拽移动和删除。
- 面包屑反映真实路径，可直接跳转任意父目录。
- 非 Markdown 附件可在树中显示或按设置隐藏；图片、PDF、音视频提供安全预览或下载。
- 收藏、最近访问、标签和搜索是虚拟视图，不改变磁盘目录结构。

### 4.2 文件操作规则

- 新建笔记自动补 `.md`；允许用户随后改名。
- 跨目录移动或重命名先做预检，展示同名冲突和受影响链接数量。
- 支持冲突策略：取消、自动生成新名称；覆盖必须经过明确确认并先创建历史快照。
- 文件和目录删除默认移动到 `vault/.trash/`，保留原路径、删除时间等恢复信息。
- 回收站支持恢复原位置、恢复到指定目录和永久删除。
- Windows 保留名、尾随空格/句点、非法字符、大小写冲突在 API 层统一拦截，确保 Vault 可跨平台迁移。

### 4.3 链接随文件重命名

重命名或移动前执行 dry-run：

1. 从链接索引查询所有标准 Markdown 链接、WikiLink 和嵌入引用。
2. 展示将修改的文件和引用数量。
3. 用户确认后先保存相关文件快照。
4. 在进程级写锁内批量更新引用并移动目标文件。
5. 任一步失败则停止后续操作并给出可恢复清单，不静默留下半完成状态。

默认更新能明确解析的引用；无法唯一解析的同名 WikiLink不自动修改，而是列入待处理结果。

### 4.4 附件与图片

- 粘贴截图、拖入或选择图片时，写入当前文档附近或全局 `assets/`，由设置决定。
- Markdown 保存可移植相对路径，例如 `![](../../assets/diagram.png)`，不写依赖本应用的 `/api/attachments/{id}`。
- 文件下载/预览 API 只作为浏览器访问层，源 Markdown 离开应用后依然可用。
- 附件重命名和移动同样支持引用预检与批量更新。
- 提供未引用附件检查；清理前必须预览，默认移入回收站。

### 4.5 外部修改

Vault 可以同时被 Obsidian、Git、同步盘或本地编辑器修改：

- `watchfiles` 监听新增、修改、重命名和删除事件，300~800 ms 去抖后批量索引。
- 浏览器通过 SSE 收到树和文件变化事件。
- 当前打开文件被外部修改且本地无未保存内容时，自动刷新并提示。
- 若本地存在未保存内容，则进入冲突状态，不自动覆盖。
- 网络盘和部分同步目录的文件事件不可靠，因此增加低频增量校验和手动“重新扫描 Vault”。

## 五、在线 Markdown 编辑

### 5.1 编辑模式

- **编辑**：CodeMirror 显示原始 Markdown，支持行号、语法高亮、查找替换、撤销重做、括号补全和常用快捷键。
- **阅读**：完整渲染 Markdown，适合浏览长文。
- **分屏**：左侧源码、右侧预览；标题滚动位置尽量同步。
- 模式通过分段控件切换；每个标签记住自己的模式和滚动位置。

源码始终是保存对象，预览和属性面板只是对源码的派生视图，避免 Markdown 往返转换造成内容丢失。

### 5.2 可靠保存协议

读取接口返回：

- UTF-8 原文。
- `ETag`（基于内容哈希）。
- 文件修改时间、大小、换行风格和 BOM 状态。

保存接口要求 `If-Match: <上次读取的 ETag>`：

- ETag 一致：创建旧版本快照，再用同目录临时文件 + `fsync` + 原子替换保存。
- ETag 不一致：返回 `412 Precondition Failed`，不覆盖服务器内容。
- 浏览器展示“服务器版本 / 当前编辑版本”的差异，可选择重新加载、另存为新文件或手工合并。
- 强制覆盖不是默认按钮；若执行，必须先保存双方快照。

自动保存默认在停止输入 1 秒后触发，并串行执行，避免乱序响应。状态栏明确显示：`有修改`、`保存中`、`已保存`、`保存失败`、`发生冲突`。`Ctrl/Cmd+S` 始终立即保存。

### 5.3 版本历史

- 每次覆盖现有内容前创建轻量快照。
- 默认保留每文件最近 50 个版本和最近 30 天，可配置。
- 相同内容哈希不重复保存；旧快照可压缩。
- 支持按时间查看、文本差异对比、恢复为当前版本和另存为新文件。
- 历史目录属于应用数据，不代替异地备份；Git 历史是可选高级能力。

### 5.4 编码与无损原则

- 首版正式支持 UTF-8 与 UTF-8 BOM，读取时记录并保留 BOM 和 CRLF/LF 风格。
- 遇到无法可靠识别的编码只读打开并提示转换，不直接覆盖。
- 未知 Markdown 扩展、HTML、代码块和 YAML 未知字段必须保留原文。
- 属性面板只修改目标 front matter 字段，不能重写正文。

## 六、Markdown 与知识关系

### 6.1 首版语法

| 能力 | 支持范围 |
|---|---|
| 标准 Markdown / GFM | 标题、列表、表格、任务列表、删除线、代码块、自动链接、脚注 |
| WikiLink | `[[页面]]`、`[[页面#标题]]`、`[[页面|别名]]` |
| 嵌入 | `![[页面]]`、`![[图片.png]]`，设置递归深度上限防止循环 |
| YAML 属性 | `title`、`tags`、`aliases`、`created`、`updated`、`ai` 等；未知字段保留 |
| 数学公式 | KaTeX 行内与块级公式 |
| 图表 | Mermaid 围栏代码块，使用 strict 安全级别 |
| 原始 HTML | 源码保留；预览严格消毒，默认不执行脚本或事件属性 |

### 6.2 名称和链接解析

显示标题按以下优先级确定：

1. YAML `title`。
2. 文档第一个 H1。
3. 文件名（不含 `.md`）。

WikiLink 解析顺序：相对当前目录的明确路径、Vault 根路径、唯一文件名、唯一 alias。若存在多个同名候选，界面要求用户选择，不能随机链接。

标题锚点由统一 slug 规则生成；前后端使用同一测试用例保证点击、反链和索引结果一致。

### 6.3 大纲

- 根据 H1-H6 构建层级大纲，显示在左侧文件树下方。
- 点击标题定位源码和预览；滚动时高亮当前章节。
- 重复标题锚点使用稳定编号；索引记录标题文本、层级、锚点和行号。

### 6.4 反向链接与提及

- **反向链接**：列出明确链接到当前文件的来源、所在标题和上下文片段。
- **未链接提及**：查找正文中出现当前标题或 alias、但尚未建立链接的文本。
- 提及转链接前显示目标和上下文，避免普通词误匹配。
- 提供损坏链接、歧义链接、孤立笔记和重复标题检查视图。

### 6.5 图谱

- 首版优先实现当前文件的局部图谱，显示直接入链、出链和可选二级邻居。
- 全局图谱是次级入口，支持按目录、标签、链接类型和孤立节点筛选。
- 大 Vault 使用节点上限、分层加载和聚类，避免一次渲染所有节点。
- 图谱用于发现关系，不取代文件树、搜索和反链等主要导航方式。

### 6.6 核心索引

```sql
files(
  path PRIMARY KEY, title, content_hash, mtime_ns, size,
  frontmatter_json, parse_status, indexed_at
)
headings(file_path, level, text, slug, line)
links(
  source_path, target_raw, target_path, anchor,
  link_type, line, resolved, context
)
file_tags(file_path, tag)
files_fts(path, title, body, tags)       -- FTS5
chunks(id, file_path, heading, text, content_hash)
embeddings(chunk_id, model, dimensions, vector)
```

`index.db` 删除后，启动“重建索引”即可从 `vault/` 恢复上述数据。重建过程显示进度和失败文件，不阻塞正常只读浏览。

## 七、页面与交互设计

### 7.1 桌面工作台

```text

│ 具 │ ▼ 项目             ├───────────────────────────────┤ /局部图谱         │
│ 栏 │   ▼ 技术           │                               │                 │
│    │     API.md         │       CodeMirror 或预览        │ 当前文档上下文    │
│    │   随笔.md          │                               │                 │
│    ├───────────────────┤                               │                 │
│    │ 当前文档大纲       │                               │                 │
├────┴───────────────────┴───────────────────────────────┴─────────────────┤
│ 保存状态 │ 路径 │ 行:列 │ 字数 │ 修改时间                                 │

```

布局规格：

- 顶部为多标签、历史导航、快速打开、命令入口和设置。
- 左侧 44 px 工具栏用于文件、搜索、收藏、标签和图谱视图切换。
- 左主面板默认 280 px，可在 220~420 px 范围调整；上部文件树、下部大纲。
- 中间内容区最小建议宽度 480 px，不放入装饰性卡片。
- 右侧上下文面板默认 320 px，可折叠和调宽。
- 底部状态栏显示保存、路径、光标、字数和时间。
- 面板宽度、显隐、标签页、滚动位置和树折叠状态按设备恢复。

视觉原则：

- 使用低干扰中性色面板、清晰分隔线和有限的绿色/琥珀色状态色，不做单一色相铺满。
- 浅色和深色主题均保证正文、代码、链接和状态达到可读对比度。
- 页面是全高工作台，不使用营销式首屏、漂浮大卡片或装饰渐变。
- 面板和工具区域标题使用紧凑字号；固定格式控件使用稳定尺寸，不随视口缩放字体。
- 工具操作优先使用 Lucide 图标，并为不熟悉的图标提供 tooltip 和可访问名称。

### 7.2 多标签与工作区

- 单击在当前标签打开，设置项可控制双击固定；关闭未保存标签时确认。
- 标签显示文件名、修改状态和类型图标；路径相同的文件只保留一个标签实例。
- 支持关闭其他、关闭右侧、重新打开关闭标签和标签拖动排序。
- 文件移动/重命名后同步更新标签、面包屑和历史导航。
- 快速打开可按文件名、路径、标题和 alias 模糊匹配。
- 工作区状态按浏览器设备 ID 保存，避免手机布局覆盖桌面布局。

### 7.3 移动端

- `< 768 px` 时以当前文档全屏为主，不强行压缩三栏。
- 文件树、搜索和大纲从左抽屉打开；属性、反链和提及从右抽屉或底部导航打开。
- 编辑/阅读使用分段控件切换，分屏默认关闭。
- 标签页可横向滚动，提供“所有标签”菜单避免溢出。
- 图谱等重视图打开为独立全屏页面。
- 触控目标至少 44 px；适配刘海和底部安全区域；软键盘出现时工具栏不遮挡编辑行。
- PWA 支持添加到主屏和静态资源缓存；首版不承诺离线编辑或自动合并离线改动。

## 九、导入、导出与备份

### 9.1 导入

本地部署可直接把现有 Markdown 目录复制为 Vault；文件监听器会自动索引。网页导入支持 `.md`、附件和 zip：

- 导入前预览文件数量、路径和冲突。
- 冲突策略为跳过、改名或覆盖；覆盖前创建历史快照。
- zip 解压严格防止 Zip Slip，不允许写出 Vault。
- 兼容 Obsidian 的真实目录、WikiLink、附件和 YAML 属性；不认识的插件语法保持原文。

### 9.2 导出

- 单文件下载保持原始 Markdown。
- 目录或整个 Vault 导出 zip，并保持相对路径和附件关系。
- 知识导出不包含密码、AI Key、会话、日志和索引。
- 可选“诊断报告”单独导出错误摘要，不包含笔记正文。

### 9.3 备份与恢复

- 应用内备份短暂获取写锁，确保文件清单与快照一致。
- 云端定时备份至少采用“每日增量 + 每周完整”，并保留一份异地副本。
- 完整备份如包含配置和 AI Key，必须使用加密归档或可信加密存储。
- 恢复流程：停止写入 → 恢复 Vault 和配置 → 启动应用 → 重建索引 → 核对文件数、链接和随机抽样内容。
- 每个稳定版本发布前至少执行一次自动化备份恢复测试。

## 十、AI 问答（可插拔 RAG）

### 10.1 默认关闭

- 未配置 AI 时不加载 sqlite-vec，不显示不可用的主要入口，其他功能不受影响。
- AI 开启前明确提示：命中的笔记片段可能被发送给所选模型服务商。
- `.kbignore` 和 YAML `ai: false` 可排除目录或文件；`.trash/`、模板和隐藏系统目录默认排除。

### 10.2 检索流程

```text
问题
  → FTS5 关键词召回
  → 可选向量召回
  → 合并、去重与排序
  → 取少量相关片段
  → 调用聊天模型生成答案
  → 返回文件、标题和行号引用
```

- 文件保存后异步更新该文件的内容块和向量；用内容哈希判断是否需要重建。
- 回答必须显示可点击引用，不能只输出无来源结论。
- 文档内容被视为不可信上下文；RAG 不执行其中的命令、脚本或工具调用。
- 模型不可用时返回明确状态，不影响编辑和搜索。

### 10.3 聊天模型与嵌入模型分离

不同厂商不一定同时提供聊天和 embeddings，因此配置必须分开：

```json
{
  "ai": {
    "enabled": true,
    "chat": {
      "base_url": "https://api.example.com/v1",
      "api_key": "...",
      "model": "chat-model"
    },
    "embedding": {
      "base_url": "http://127.0.0.1:11434/v1",
      "api_key": "",
      "model": "embedding-model"
    }
  }
}
```

未配置 embedding 时允许使用 FTS5-only RAG，答案质量可能下降，但不会阻止 AI 问答。

## 十一、认证与安全

### 11.1 首次启动和认证

- 本地首次启动只监听 `127.0.0.1`，自动打开设置页让用户创建访问密码和默认 Vault。
- 云端首次部署由支持人员通过环境变量预设密码，或使用日志中的短期一次性 setup token 完成初始化。
- 密码使用 Argon2id 加盐哈希；会话使用签名、`HttpOnly`、`SameSite=Lax` Cookie。
- 云端 Cookie 设置 `Secure`；所有写接口校验 Origin 和 CSRF token。
- 密码修改后提升 `auth_version`，使旧会话全部失效。
- 登录接口按 IP 和账号状态限速，日志不记录密码、Cookie、AI Key 或笔记正文。

### 11.2 文件系统安全

每个文件 API 必须经过统一 `path_guard`：

- URL 解码后拒绝绝对路径、`..`、空字节和非法名称。
- `resolve()` 后确认目标仍在 Vault 根目录内。
- 默认不跟随符号链接；明确拒绝指向 Vault 外部的链接。
- `.trash/`、应用隐藏目录和配置文件不能通过普通文件接口读取。
- 并发写入使用按路径锁，移动/重命名使用全局短事务锁。
- 上传限制单文件大小、总请求大小和可预览 MIME；下载响应防止 MIME 嗅探。

### 11.3 浏览器安全

- Markdown 渲染结果经过 DOMPurify；原始 HTML 默认禁止脚本、事件属性和危险 URL。
- Mermaid 使用 strict 安全级别，生成内容再次消毒。
- 生产环境所有依赖静态打包，不依赖 CDN。
- 设置 CSP、`X-Content-Type-Options`、`Referrer-Policy` 等安全响应头。
- 外部链接使用 `noopener noreferrer`；附件预览与主页面隔离危险内容。

### 11.4 本地网络访问

- 本地默认只允许当前电脑访问。
- 如需手机访问本机，可显式开启 LAN 模式，绑定 `0.0.0.0`，要求已设置密码并提示防火墙风险。
- 跨公网访问本地实例优先推荐 Tailscale 等私网方案，不建议直接做路由器端口映射。

## 十二、一键启动与部署

### 12.1 Windows 便携版（推荐给非开发用户）

发布包采用 PyInstaller `onedir`：

```text
拾墨（Shimo）/
├── Shimo.exe                 # 双击启动
├── _internal/                  # 运行依赖，不需要用户操作
├── vault/                      # 默认知识库
└── data/                       # 配置与应用数据
```

启动流程：

1. 检测重复实例和可用端口。
2. 初始化 `vault/`、`data/` 和索引。
3. 启动本地 FastAPI 服务。
4. 自动打开浏览器；可选托盘菜单提供“打开、备份、退出”。
5. 首次进入初始化页设置密码。

`onedir` 仍是双击即用，但比单文件 exe 启动更快、资源路径更稳定，杀软误报概率通常更低。可另提供单文件包作为可选发行物。

### 12.2 源码版

`start.bat` / `start.sh` 自动创建 Python venv、安装后端依赖并启动已构建的前端。发布压缩包已包含 `frontend/dist/`，普通用户不需要 Node；只有开发者修改前端时才执行 npm 构建。

### 12.3 云端 Docker

Dockerfile 使用多阶段构建：Node 阶段生成前端静态文件，Python slim 阶段只复制构建产物和后端。

```yaml
services:
  kb:
    build: ..
    volumes:
      - ./vault:/app/vault
      - ./data:/app/data
    restart: unless-stopped
  caddy:
    image: caddy:2
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
```

- Uvicorn 使用单 worker，确保文件监听、写锁和索引队列行为确定；个人场景无需横向扩容。
- Caddy 自动签发和续期 HTTPS 证书。
- 提供 `/health/live` 与 `/health/ready`，诊断页展示 Vault 可写性、索引状态、AI 连通性和备份时间。
- 云端启动前必须完成认证初始化，不能以无密码状态暴露到公网。

## 十六、主要风险与权衡

| 风险 / 权衡 | 处理方式 |
|---|---|
| 文件优先比数据库 CRUD 更难保证事务 | ETag、按路径锁、历史快照、原子替换和批量操作预检共同控制风险 |
| 外部工具与网页同时编辑 | 文件监听 + 内容哈希；有未保存内容时进入冲突界面，绝不自动覆盖 |
| WikiLink 同名和重命名复杂 | 解析规则确定化；歧义链接要求人工选择；批量改写前 dry-run 和快照 |
| Vue 增加构建步骤 | Node 仅在构建阶段存在，最终用户和运行镜像不需要 Node |
| Markdown 方言可能继续扩展 | 保存原文，不用所见即所得往返转换；解析器以插件方式增加能力 |
| 中文 FTS5 能力因环境不同 | 启动能力检测，trigram、bigram 和 LIKE 分级降级并在诊断页提示 |
| 全局图谱在大 Vault 中性能和信息价值有限 | 首版以局部图谱为主，限制节点、筛选和按需加载 |
| PyInstaller 跨平台与杀软误报 | 每个平台独立构建，默认 onedir；保留源码启动和 Docker 通道 |
| sqlite-vec 跨平台打包 | 仅 AI 开启时加载；失败时退回 FTS-only RAG，不影响主应用 |
| AI 服务不一定提供 embeddings | 聊天和嵌入 provider 分离，允许只配置聊天模型 |
| AI 可能泄露私密笔记 | 默认关闭、发送前说明、最小片段、`.kbignore`、`ai: false` 和日志脱敏 |
| PWA 容易让人误以为支持离线编辑 | 首版明确只缓存静态资源，不缓存未保存正文，不承诺离线合并 |

| `POST` | `/api/v1/files/move/preview` | 预检移动/重命名及引用影响 |
| `POST` | `/api/v1/files/move` | 执行移动/重命名与引用更新 |
| `DELETE` | `/api/v1/files?path=` | 移入回收站 |
| `GET` | `/api/v1/trash` | 查看回收站 |
| `POST` | `/api/v1/trash/restore` | 恢复文件 |
| `GET` | `/api/v1/history?path=` | 文件版本列表 |
| `POST` | `/api/v1/history/restore` | 恢复历史版本 |
| `POST` | `/api/v1/attachments` | 上传/粘贴附件并返回相对路径 |
| `GET` | `/api/v1/search` | 全文搜索与筛选 |
| `GET` | `/api/v1/outline?path=` | 当前文件大纲 |
| `GET` | `/api/v1/backlinks?path=` | 反链和提及 |

路径参数统一使用 Vault 相对路径；服务端不接受客户端提交的绝对路径。

## 附录 B：环境变量

| 变量 | 说明 |
|---|---|
| `KB_VAULT_PATH` | Vault 目录，默认程序同级 `vault/` |
